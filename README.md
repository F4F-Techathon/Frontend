# 饭店请就位

Vue 3 + TypeScript + Pinia 的移动端选餐体验，复用 `damo.html` 中的 SVG 角色、复古配色与剧场视觉。

## 本地运行

```sh
npm install
npm run dev
```

```sh
npm test       # 语音、LLM 代理、需求纠正与重试、筛选、用户定店、会话恢复
npm run build  # TypeScript 检查与生产构建
npm start      # 生产运行：前端静态文件 + 需求整理 API，默认 3000 端口
```

需要 Node.js 22.18+（22.x）或 24.12+。

## 页面流程

首页 → 语音表达与 Orb 逐轮整理需求 → 用户确认 → 滑卡选店 → 集合开场 → 餐馆辩论 → 用户选定饭店 → 餐厅详情。

说完一轮后，Orb 显示结构化需求卡，并提出至多一个补充问题。可以继续语音修改预算、人数、偏好和忌口；每轮成功后更新同一份需求，不自动跳页。点击「就这样，去挑饭店」才把确认结果用于筛选。失败时保留上一份需求和本轮发言，可重试原文或重新说；未整理的更改会阻止按旧需求继续。对话草稿保存在当前浏览器，返回时可接着聊，开始新饭局会清空。

左滑跳过、右滑邀请，也支持键盘方向键；卡片下方常驻小地图、当前餐厅地址和直线距离，随滑卡同步位置，无需展开；不设操作按钮。支持取消邀请，不会自动填满选手。划完这一轮或选手就位后，中央出现可点击的场记板，合板动画完成后衔接地图集合和拉幕布入场；没有选够时可以再看一轮。右上角可调整条件，硬条件排除不符合或相关信息未知的餐厅，偏好作为讨论内容，饭店顺序保持稳定。滑卡进度、选择、讨论历史与新条件保存在当前浏览器。讨论页右上角的「做出决定」打开饭店选择，用户选中并确认后才生成结果；讨论结束也会等待用户选择。依据随当前发言常驻展开，需要细看时可暂停；打开历史会暂停讨论，通过播放按钮继续。

## 地图配置

将 `.env.example` 复制为 `.env.local`，设置高德 Web JS API Key 与安全配置。本地配置文件已被 `.gitignore` 忽略。环境变量变更后需要重新启动 Vite。

地图使用高德 JS API 2.0，支持地点搜索、定位、平移缩放和候选标记。地图在滑卡时预载，开场时展示集合动画；加载失败不影响滑卡和入场。生产环境可通过 `VITE_AMAP_SERVICE_HOST` 设置安全代理，参见[高德安全配置文档](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)。

## 数据与服务边界

- 餐厅、价格、评价和发言来自 `src/data/` 中的演示数据，不代表真实商家或真实用户评论；依据中逐条保留数据性质与来源。`EvidencePanel` 直接接收依据数据，支持纯评价文字、图片和图文混排，讨论页随当前发言更新并保持展开；`text`、`images` 和日期均可按实际资料提供，来源链接可跳转原文。
- 主图是按菜系选配的示意照片，使用本地 WebP 文件；[摄影师与图片来源](src/assets/images/restaurants/CREDITS.md)保存在素材目录中。
- 地图底图与地点搜索调用高德真实服务；餐厅演示坐标集中在上海静安寺附近。
- 初始需求由真实 LLM 整理为经过校验的完整快照，确认后直接应用，避免重新解析旧发言而覆盖已纠正的预算。菜系排除、不能吃辣、多个过敏原和食材忌口会参与硬条件筛选；缺少必要食材资料的演示餐厅会被排除。软偏好不会伪装成商家事实。
- 具体地名由高德 POI 服务解析；有多条匹配时在页内选择。明确“我附近”或只给距离限制时，确认后请求真实定位。未指定位置与距离时不擅自增加距离硬条件，地图仍使用标注的演示搜索中心。
- 辩论仍按当前选手和条件生成本地固定轮次，讨论内的补充条件使用本地规则；最终饭店由用户自行选择，尚未连接多智能体后端。
- 语音目前使用浏览器语音识别，需要允许麦克风；需求页和舞台均为长按说话、松开发送，短点或切到后台会取消录音。讨论中的识别内容显示在原有对话卡片中，说完继续讨论。播放使用设备语音合成，尚未接入实时语音后端。
- 未接入预订、电话或商家交易服务，不展示预订成功等虚构结果。

## LLM 配置与部署

在被忽略的 `.env.local` 中配置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。这三个变量只供服务端使用，不加 `VITE_` 前缀，不提交密钥。当前模型为 `gemini-3.8-flash`，接口使用服务商文档中的 [Chat Completions 协议](https://api-gpt-ge.apifox.cn/210339408e0)。

浏览器只请求同源 `POST /api/intake`；代理限定模型、输入长度与响应结构，45 秒超时，浏览器断开后会取消上游请求。不会把上游原始报错或密钥返回页面。

`npm run dev` 和 `npm run preview` 已挂载这个接口。生产环境在项目根目录执行 `npm run build` 后用 `npm start`，由 Node 同时提供 `dist/` 和 API；`PORT`、`HOST` 可由环境变量设置。部署需要保留 `server/`、`src/lib/intakeProtocol.ts` 和 `package.json`。只有静态托管时，需要另行部署这个 Node API 并为 `/api/intake` 设置同源转发。

## 主要代码

- `src/views/`：需求、滑卡、讨论、结果等页面
- `src/components/`：SVG 角色、舞台关联界面、筛选、地图、通用抽屉
- `src/stores/dining.ts`：跨页面状态、选择、历史与恢复
- `src/stores/intake.ts`：多轮需求草稿、请求取消、失败重试与恢复
- `src/lib/intakeProtocol.ts`：浏览器与服务端共用的需求结构和校验
- `server/intake.ts`：LLM 提示词与受限代理接口
- `src/data/`：演示餐厅、证据、发言与类型
- `src/lib/characterRig.js`：从参考演示提取的角色绘制模块
- `src/lib/filtering.ts`：需求解析、硬条件过滤与距离计算
- `src/lib/amap.ts`：高德 SDK 加载与错误重试

## 仓库与日常开发

远程仓库：[F4F-Techathon/Frontend](https://github.com/F4F-Techathon/Frontend)。本地直接在本项目目录开发。

```sh
git pull --rebase
# 修改代码后
npm test
npm run build
git add .
git commit -m "说明本次修改"
git push
```
